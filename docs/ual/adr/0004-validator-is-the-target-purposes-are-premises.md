# The whole validator program is the target; purpose-level properties lower to premises

An Aiken validator compiles to one UPLC program whose purpose dispatch is generated by the compiler; the blueprint merely lists that one program once per handler. A UAL target must be exact bytes, so the target is the validator (id `module.validator`, the shared script hash) and never a handler. Users may still write a property "for `v.spend`"; the producer lowers it to the complete proposition with an explicit premise on the script context's purpose, and only that complete proposition reaches the assurance document. Compiling a handler body in isolation and claiming anything about the deployed script is ruled out as unsound.

## Consequences
- `for v.else` lowers to the negation of every purpose `v` handles.
- Lowering targets CardanoLedgerApi's V3 `ScriptInfo` constructors.
- The consumer also requires each validator checking target to select a `purpose`. In V3 every invocation takes the same single context argument, so that selection picks a calling convention and does not constrain the context; the premise is what gives a handler-scoped property its meaning. The producer sets both. The interface lists all six invocations, since the compiled program can be invoked under any purpose.
