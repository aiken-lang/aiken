# UAL decisions log

## 2026-11-04 — UAL-02: standalone document contracts

- Added `aiken-ual` through the workspace's existing `crates/*` membership. It has no dependency on `aiken-lang`, `aiken-project`, `uplc`, Lean or Z3. The existing `cryptoxide` dependency supplies SHA-256; `jsonschema` 0.33 supplies draft-2020-12 validation with default HTTP/file retrieval features disabled and an explicit rejecting retriever, including under Cargo feature unification.
- Followed [PlutusCoreBlaster `1c23de8f35fdc5decf6f126c7b56ed6649e4a57f`](https://github.com/input-output-hk/PlutusCoreBlaster/tree/1c23de8f35fdc5decf6f126c7b56ed6649e4a57f/PlutusCore/UPLC/BlueprintEncoding), not moving upstream. Vendored assurance-v2, checking-context, interface, value and blueprint schemas and `scripts/assurance-workspace.json` byte-for-byte; `crates/aiken-ual/schemas/PIN` records their origin. No old integration branch code was used.
- The ticket calls the document contract UAL 0.6. Per plan §4.1, the pinned coordinated workspace identifies UAL 1.0 (`1f7ab84`); the plan records this as the 0.6-draft rename without a content change. Wire schema identifiers remain the pinned `cipXXXX` / compiled-interface-v1 identifiers. The model does not invent a top-level UAL version field: assurance preamble and language registries retain their explicit versions. Temporal operators and Lean elaboration remain out of scope.
- Canonical file encoding is recursively lexicographically sorted JSON object keys, serde_json's two-space pretty formatting (including multiline nonempty arrays), UTF-8 strings and one trailing LF. Array order is preserved. Explicit recursive sorting makes bytes independent of `serde_json/preserve_order`. This is a fixed producer encoding, not RFC 8785. Hash existing files as raw bytes; parsing and normalizing them before hashing would invalidate bindings. Independent golden fixtures cover each document, including evidence-bearing assurance.
- The schema's semantics variants are uppercase `A`–`E`; Aiken's future lowercase `c`/`e` syntax must lower to `C`/`E`. Universal validator checking targets contain validator id, purpose and parameter mode, not a template script-hash field. Their template hashes live in the digest-bound blueprint; applied targets additionally carry `appliedScriptHash`. Function targets carry SHA-256 plus a complete interface copy. The crate follows these pinned shapes, including schema-valid ledger-unit/applied forms, without claiming the pinned consumer executes every schema-valid form.
- The base blueprint schema contains legacy argument/parameter references whose files do not ship in the pinned set. The compiled-interface dialect reaches only its exact `$defs/preamble`. Unlike the consumer's on-demand resolver, the Rust validator eagerly crawls resources; the offline registry therefore exposes that unchanged preamble subtree under the base `$id` and rejects validation through the base root. Vendored bytes are untouched. Missing legacy refs are not downloaded or replaced by permissive schemas. Tests exercise preamble constraints and rejection of the base root.
- No environment schema ships at this pin. `schemas/environment.schema.json` is explicitly local and derived from `Assurance.lean::captureCheckingEnvironment`: format `blaster-loaded-environment-v1`, compiler/solver/module SHA-256s, optional native library SHA-256, and fixed solver options `60/100000/0`. There is no `$schema` in the manifest. Shape/hash validation is not equality with a live loaded environment; the consumer owns that check.
- Models preserve absent versus present-empty optional collections and retain unknown fields where upstream objects are open. Closed objects reject unknown fields; empty tagged struct variants are used because serde unit variants otherwise silently discard extra members. `ValueSchema` retains extensible schema JSON without inventing a second type/encoding system. Structural validation does not resolve value-definition graphs or analyze formal source.
- `function_digest` hashes hex-decoded `compiledCode`, including its single CBOR wrapper, with bounded decoding scratch space. Script hashes are carried as lowercase blake2b-224 hex and shape-checked, not recomputed by this crate. `validate_bindings` checks exact blueprint/context bytes, function code/interface identity, target coverage and evidence bindings; `validate_environment` separately checks manifest bytes. Callers supply artifact bytes and resolve paths; no implicit filesystem/network access occurs. Validator references resolve by id, then unique title, matching the pinned consumer.
- Evidence-bearing `verified-assurance.json` uses the same assurance document model. `EvidenceRecord::smt_check` binds a caller-reported outcome to a context digest, tool and artifact; callers add the scoped script/function hashes before validation. Construction does not invoke a solver or establish trust. Producer generation remains evidence-free; UAL-12 can use this write API after checking. Historical evidence is readable, but explicit binding validation rejects stale context/function/script hashes rather than treating it as current verification. The pinned schema's single `scriptHash` per evidence record remains unchanged.
- Smoke exercised schema-checked emission, disk round-trip, environment binding and rejection after a whitespace-only blueprint edit with Lean/Lake/Z3 absent from PATH. No consumer invocation or semantic verification was performed.
- Verification passed: 21 crate tests, the same tests with `serde_json/preserve_order`, both workspace build commands, workspace formatting, clippy with warnings denied, workspace tests and bounded `aiken-acceptance`. A fresh-target offline build also passed with Lean/Lake/Z3 absent from PATH. No existing snapshots were changed.

## 2026-11-04 — UAL-03: opaque annotation trivia

- Compatibility audit: searched every `.ak` file in public [aiken-lang/stdlib at `8e43f28e39f5394f9913109a75ad52054ff29c71`](https://github.com/aiken-lang/stdlib/tree/8e43f28e39f5394f9913109a75ad52054ff29c71) (58 files) and [aiken-lang/fuzz at `4624a796376b78a8b84257e2eded0cd313220a0e`](https://github.com/aiken-lang/fuzz/tree/4624a796376b78a8b84257e2eded0cd313220a0e) (5 files), plus the local `examples/` tree, for the literal `//@`. No occurrences were found, including comments beginning with that prefix. Public source files were read at those exact revisions; no supplemental checkout or dependency was added.
- Followed plan §2.1 and ADR-0002: delimiters are lexical syntax, but region bodies and kind names are opaque here. Unknown kinds are neither errors nor warnings in UAL-03; their interpretation belongs to UAL-05. The audit found no existing usage requiring the ticket's compatibility-warning fallback. Consumer pins in §4.1 are unchanged; this change neither invokes nor downloads a consumer.
- `ModuleExtra::assurance_comments` stores delimiter-inclusive UTF-8 byte spans; its same-named iterator borrows the exact region text from the source. The added field defaults when older metadata is deserialized. Existing comment kinds still exclude their prefixes. An internal trivia token is removed before parsing; no annotation AST node or grammar production was added.
- A closer is eligible after Unicode whitespace (`char::is_whitespace`), including line endings; a non-boundary `x@//` stays in the body. The first eligible closer ends the region. Strings and existing ordinary/doc/module comments shield delimiter-like text. A nested opener is diagnosed at its three bytes; an unterminated region is diagnosed from its opener through EOF. Interior blank lines never enter ordinary empty-line trivia.
- For modules containing regions, the formatter merges all comment kinds in source order and emits delimiter-inclusive text without reindenting region interiors. This preserves adjacent documentation and decorator ordering. Definitions and imports retain source order rather than sorting imports across annotation anchors. Modules without regions retain the existing formatting path. Region bytes include CRLF, tabs, trailing spaces and Unicode; whitespace outside the delimiters remains formatter-controlled.
- Runtime verification exposed an existing upstream coordinate bug: `LineNumbers::line_number` compared a line index with the last line's byte offset, rejecting nonzero positions in single-line files and some short final lines. The new EOF diagnostic reached this path in the LSP. Added a failing-before/passing-after regression and corrected bounds to use source length, retaining the existing metadata shape and empty-source behavior. No existing parser or formatter snapshots changed.
- Smoke proof: the built CLI formatted three regions around definitions, documentation and a decorator twice, preserving every region byte (including `∀ → ¬ λ`, `//`, `@`, CRLF and whitespace). Both malformed forms produced labelled CLI diagnostics. A live stdio LSP session returned the same formatting edits, preserved idempotence, published exact ranges for nested and single-line unterminated regions, then successfully formatted a corrected document and shut down cleanly. No LSP protocol changes were needed.
- Verification passed: `cargo build --workspace --all-targets`, `cargo build --workspace`, `cargo test -p aiken-lang` (609 unit tests and 2 doc tests), `cargo fmt --all -- --check`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo test --workspace`, and bounded `aiken-acceptance`. No dependencies, release configuration, protected code-generation/evaluator paths, or snapshots were changed.

## 2026-11-04 — UAL-04: onchain target decorators

- Added `@onchain(steps: n, semantics: c|e)` for public/private top-level functions and validators. Settings are checked as ordinary type errors: both are mandatory, keys and the decorator cannot repeat, unknown keys are rejected, steps must be positive, and semantics accepts only C/E in either case. Steps use the existing `aiken-ual` document model's positive `u64` range (1–18446744073709551615); decimal, hexadecimal and numeric underscores follow ordinary Aiken integer syntax.
- Kept declaration decorations in `Module::definition_decorators`, keyed by the underlying declaration's exact `Span`, rather than changing generator-facing function/validator structs. Both untyped and typed modules retain this metadata; the serde field defaults for older metadata. Raw argument values preserve source spelling for formatting and invalid-setting diagnostics. Inference normalizes semantics to uppercase and integer values to decimal. Existing data-type/constructor decorators retain their current storage. No assurance documents are emitted, and protected generator/evaluator files are unchanged.
- Ineligible tests, benchmarks, constants, aliases, imports, data types and constructors receive decorator-context type errors. Decorated imports remain distinct until this validation instead of being merged away. Syntax outside declaration/constructor decorator positions remains an ordinary parser error. Existing `@tag`/`@list` context rules are unchanged.
- Function eligibility runs after whole-module inference/generalization and before private types are removed. It reuses the existing opaque-type registry and ABI diagnostics and mirrors export schema traversal through containers and instantiated constructor fields. It rejects opaque, free/unbound and function types in arguments or results. As in blueprint `tipo_or_annotation`, a `Data<T>` boundary uses T's schema; a failing regression exposed the need to check these erased annotations as well. Validator ABI checks remain unchanged.
- The formatter retains argument order, integer spelling and semantics case in source, while typed metadata is normalized for later emission. Decorated modules reuse UAL-03's source-ordered trivia handling so ordinary/doc/module comments and opaque annotation regions stay ordered around decorators. No consumer pins moved and no old integration-branch code was used.
- CLI smoke exercised formatting twice, type checking, execution of a test calling decorated private/public functions, and blueprint building for a decorated validator. All succeeded; the second formatting pass was byte-identical and the adjacent opaque annotation region was preserved.
- Follow-up only: `uplc::machine::Machine::step_and_maybe_spend` already increments per-kind and total pending step counters, then clears them when charging the budget. A cumulative counter appears cheap, but its relationship to the pinned consumer's CEK transition budget must be specified and checked before exposing it. No counting or evaluator behavior changed here.
- Blueprint compatibility: built all 139 example projects with the original and modified CLIs against the same resolved public dependencies. All complete blueprint JSON values matched, including all 77 validator entries' `compiledCode` and hashes. This includes `examples/hello_world` and `examples/gift_card`; adding/removing decorators on the smoke validator also left its blueprint unchanged. Generated lockfile metadata was restored.
- Diagnostics: 48 new error snapshots cover invalid settings, declaration contexts and local/imported interface types, including erased `Data<T>` annotations. Six existing module-parser snapshots changed only to include the empty `definition_decorators` field; all were reviewed individually. Ten invalid CLI scenarios also produced the expected ordinary type diagnostics rather than parser errors.
- Final verification passed: `cargo build --workspace --all-targets`, `cargo build --workspace`, `cargo fmt --all -- --check`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo test --workspace`, and bounded `aiken-acceptance`. The language suite includes 627 unit tests and 2 doc tests. No dependencies, release/CI configuration or protected code-generation/evaluator paths changed.
