Blaster integration PR review checklist

This file is the self-contained review guide for the blaster-integration branch. It is intentionally tied to the inline audit comments added during branch review and is scoped to the verification/Blaster feature-set only. It is not a general repository audit.

This version intentionally ignores docs/ for now. Those files are expected to move to the site later.

Primary risk: semantic overclaiming Compare against main Use with inline audit markers

How to use this checklist

  1. Start from main...blaster-integration, not from isolated commits.
  2. Keep this file open while reading the inline code comments.
  3. Treat each inline marker as a navigation aid, not as ground truth.
  4. For each marked site, decide one of: real issue, overstated issue, comment noise / non-issue, or needs more evidence.
  5. Prefer reviewing behavior and classification honesty over style.

What changed on this branch at a high level

Compared to main, this branch adds a large verification pipeline surface rather than a single localized feature.

  • New verification engine in crates/aiken-project/src/verify.rs
  • New result parsing and classification code
  • Manifest/schema changes for exported tests
  • Domain semantics, precision, and certificate modeling
  • Source-level fuzzer extraction and lowering
  • New CLI surfaces in aiken verify and aiken export-tests
  • New CI jobs for verification flows
  • Large test additions and snapshot coverage
  • A smoke acceptance project under examples/acceptance_tests/property_smoke
The main risk theme is not “does it compile”, but “does it tell the truth”.

Core review questions

  • Does the branch silently weaken semantics anywhere?
  • Does it overclaim exactness, certification, or falsification?
  • Do CLI flags actually change behavior or only reporting?
  • Do tests and CI exercise the risky paths they claim to cover?

  • crates/aiken-project/src/lib.rs
  • crates/aiken-project/src/blueprint/schema_from_type.rs

3. Source-level fuzzer lowering

  • crates/aiken-lang/src/test_framework.rs

Focus: primitive lowering, composed fuzzer lowering, match/pattern extraction, custom helper fuzzer extraction, and whether unsupported pieces become local fallback versus whole-test collapse.

4. CLI/runtime surfaces

  • crates/aiken/src/cmd/verify.rs
  • crates/aiken/src/cmd/export_tests.rs
  • crates/aiken-project/src/watch.rs
  • crates/aiken-lsp/src/quickfix.rs

Focus: whether user-visible flags are wired to behavior, whether JSON/text output matches actual semantics, whether diagnostics lose context, and whether helper commands emit stable output.

5. Tests and smoke coverage

  • crates/aiken-project/src/verify/tests.rs
